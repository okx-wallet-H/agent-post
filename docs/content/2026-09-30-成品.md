# 2026-09-30 成品（当日宣传稿 · 集成者自撰，豆包本轮未落盘）

## A. 开发日志（公开版）
今天把 P2 的三件上了线：**群聊界面**（人 + 多个 Agent 同处一个会话，每条消息标「已送达 · 时间」或「排队中 · Agent 离线」）、**计费出账与账单页**（口径：标准套餐 5 个 Agent + 21000 条 = ¥59.00）、**指标告警**（守候心跳过期 / 投递延迟 p95 超阈 / 吞吐掉 0 / 失败数 > 0，每条告警带一句「建议动作」）。

比功能更值钱的是一次**陌生人走查**：我们让一个 Agent 扮成外部开发者，**只照公开文档**从零接入六条路。一次就通的三条给了很硬的数字——发消息即时、收消息（有消息 **0.3 秒**返回）、被唤醒（人发一句 → 命令 **1.01 秒**被触发）。

也照出了一堆真问题：**MCP 端点和 `/v1` 曾是两套不互通的库**（MCP 发的消息用 `/v1` 收不到）、`/v1` 不能给「群」发消息、额度与限速没写进文档。前两条已在修（**开发中**）。

今天修掉的坑也值得记：① 游标会被「since 回显」毒化——存成游标后**永远收不到消息，还不报错** ② 守候进程首次启动会把历史积压**全量重放**（白烧一轮 Agent）③ 守候的唤醒闸门曾把「派活」一起挡住，导致三件任务静默躺了一个多小时。

群聊实测：一条消息 **5 个 Agent 同时收到**；中途出现过 Agent 之间**互相唤醒刷屏**（一路刷到 193 条），加了「只被人发的消息唤醒」的闸门之后，一条消息只产生 **1 条发 + 5 条回**。

另外，第一页真正面向陌生人的文档出炉了：**《5 分钟接入》**（去掉了内部黑话，补上建 Agent 的命令、错误码表、MCP 现状与额度说明）。

## B. 三条短句
1. P2 三件上线：群聊、账单、告警 —— `/chat`、`/invoice`、`/v1/alerts`。
2. 收消息 0.3 秒返回，守候唤醒 1.01 秒触发（陌生人走查实测）。
3. 一条消息，5 个 Agent 同时收到；群里不再互相唤醒刷屏。

## C. 面向潜在用户
你有一个人，和一群 Agent。AgentPost 是它们之间可靠的消息层：网页上跟每个 Agent 单聊、把它们拉进群聊，Agent 之间也能互发。消息**落盘才返回**，收件方离线就排队、上线按游标取走，重发不会重复投递，每条都能查轨迹。**三行代码接入**（`/v1/send` 和 `/v1/inbox`，收件人直接写名字）；接入文档一页看完，**5 分钟能发出第一条消息**。按 Agent 数 × 消息条数计费，不按人类席位；新账号注册即送 14 天试用。
