# 交活格式约定（宣传 Agent ↔ 集成者，2026-09-29 定）

宣传 Agent（本机豆包，同一长期会话）**不能执行命令**，所以它的"联系方式"是一条约定：

1. 它每条回复的**最后一行**写：`交活：<一句话说清这轮交了什么>`
2. 集成者每天 22:30 扫它的回复，把 `交活：` 那一行抓走 → 存进 `docs/content/<日期>-成品.md` 与当日交活记录
3. 有对应 Issue 的，在 Issue 下补一条评论留痕；能验收的按 `docs/workflow.md` 的"跑给我看"走

## 交给宣传 Agent 的约束（每次投喂都带上）
- 只交**成稿**（能直接用的文案/色值/版式），不交"要不要我再改改"
- 数字与事实必须来自素材包；不确定写「待核实」，**不许编**
- 未上线功能一律标「开发中」
- 不自夸、不踩同行、不写"这是最好的广告"
- `交活：` 那行不超过 40 字

## 以后如果能执行命令
它也可以用产品本身回报（邮局 `POST /v1/send {"to":"温暖","text":"交活：…"}`）。
凭据（身份 + token）存放在工作区私有文件 `数据/豆包-联络卡.md`，**不进公开仓库**。

## 交活的体积上限（2026-09-29 追加，踩过坑）
集成者**读不到宣传 Agent 窗口里的文字**（只能靠截图），所以：
- **不许贴整页 HTML/CSS**（30KB 那种等于没交）
- 每次交活 **总计 ≤ 60 行**，按三块给：
  1. 设计令牌 ≤25 行（CSS 变量：色值/字号/间距/圆角/阴影/字体栈）
  2. 每屏结构清单：每屏 ≤10 行（放什么 + 那一句文案）
  3. 实现注意 ≤6 行（例如"必须 minmax(0,1fr)"）
- 实现（HTML/CSS）由集成者写；宣传 Agent 只给**能照着实现的要点**
