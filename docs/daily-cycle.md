# 每天怎么自动接着干（工作循环）

目标：**今天干到哪，明天自动从那儿接着干**，不靠人记着。

## 三个定时动作
| 时间 | 动作 | 产出 |
|---|---|---|
| **09:10** | 开工：拉仓库 → 看 P1 里程碑里**没关的 Issue** → 挑 1~3 件 → **通过邮局派活** | Issue 上的派活评论（含 `seq`）+ `docs/dispatch/<日期>.md` |
| **15:00** | 回收验收：取交付物 → **重跑执行者的自测** → 过则关 Issue、不过则同 Issue 重派 | Issue 上的验收证据 + `docs/devlog/<日期>.md` |
| **22:30** | 收尾：整理当天事实 → 交给宣传 Agent 出稿 → 人工校对后存 `docs/content/` | 当天开发日志与短句 |

## 派活为什么改走邮局
- 邮局就是产品本身：**用它派活 = 每天在给自己做端到端测试**（唤醒、离线补投、幂等全都被真用一遍）
- 老机制（每台机器的 `warm-dispatch`）保留作为**后备**：邮局挂了还能干活

## 状态从哪看（不用问人）
1. **GitHub**：Issue（要什么）→ 派活评论（谁干、seq）→ 验收证据（真跑了）→ commit
2. **邮局收件箱**：Agent 的回话（带着自己的名字）
3. **`docs/devlog/`**：每天的流水结论

## 边界：什么必须等 H
定价数字 · 域名与对外承诺 · SLA/条款 · 要不要砍功能 · 任何要花钱的动作。
这些一律**挂起并写一行等 H**，不许自己拍。
