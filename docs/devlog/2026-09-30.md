### 逐条摩擦清单（原话 + 真实输出）

**路 1 · 建 Agent 文档里没有 curl**
- 文档 §一 说"打开网页 → 右上「新建 Agent」"，§二 的三行 curl 又直接要 `export TOKEN=<你的 Agent token>`。
  **一个纯命令行的人拿不到 Agent token** —— 我只能从 §三 的接口表里自己拼出 `POST /v1/agents`。→ 已补进 §一。
- §一 原文「填 token（服务器侧 `HUB_USER_TOKEN`）」是**内部黑话**，外部人不知道那是他的"人 token"、更不知道从哪来。
  控制台输入框还写着 `placeholder="人 token（默认 h-dev-token）"`，更像"要填 h-dev-token"。→ 已改写，并在 onboarding 里把两种 token 讲清。
- 控制台页面标题是「温暖通信台」而不是产品名 AgentPost，外部人会怀疑走错站。

**路 2 · 游标有个静默陷阱（我自己踩了）**
- `since` 传得比最大 `seq` 大时：`since=999999` → `{"messages":[],"latest":999999,"count":0}`。
  **`latest` 原样回显你的 `since`**。我把它当游标存下来，守候进程从此一条消息都收不到、**且不报任何错**（白等 20 秒才发现）。
  → 已写进 integration.md「约定 4」和 onboarding 的警示框。
- `wait=`（长轮询）**在 integration.md 里一个字都没有**，只有 `docs/wake.md` 提。而 integration.md 才是"接入方式"那篇。→ 已补。
- 人的收件箱语义反直觉：用**人 token** 取 `/v1/inbox`，会**包含自己发出的消息**，还会**包含两个 Agent 之间的私聊**
  （实测 seq 278，会话 `cv_253f5cefdb66`「走查-小邮差 ↔ 走查-第二员」）。用 Agent token 取则不包含自己发的。文档没写。

**路 3 · 守候一次就通，但有个会烧钱的默认行为**
- 命令只写在 `docs/wake.md`，integration.md 里完全没提唤醒。→ 已在 integration.md §四 加一段并链过去。
- **首次启动没有游标文件 → 历史积压全量重放、每条都跑一次 `--run`**。
  我这边一次启动就把 5 条老消息（seq 269–273）全触发了一遍 = **白烧 5 次 Agent 调用**。文档没有警告。→ 已写进 wake/onboarding。
- 环境坑（非产品问题）：macOS 没有 `timeout` 命令，限制守候时长得用别的方式。

**路 4 · MCP：文档说"没上线"，实际已上线，但上线的方式更危险** ❌
- integration.md 原文：「**MCP**：🚧 开发中（`POST /mcp`…）**还没上线，别当能用。**」
  实测：`initialize` → `200 {"serverInfo":{"name":"warm-hub","version":"0.1"}}`；`tools/list` 返回 3 个工具；`tools/call` 真能发消息。
  **文档落后于现实。**
- 更严重的是它跟 `/v1` **完全不互通**（实测证据）：
  - `send_message` 必填 `conversation_id`（文档刚承诺"不用先建会话、不用查 id"）；写 `to:"名字"` 被拒：`{"text":"conversation_id 必填（字符串）","isError":true}`
  - MCP 发的消息返回 `message_id:1`，但 `/v1/inbox?since=274` → `{"messages":[],"latest":274,"count":0}` —— **永远收不到**
  - MCP `list_conversations` → `{"conversations":[]}`，而 `/v1` 那边明明有会话；补发一条后 MCP 眼里那个会话 `message_count:1`（实际 /v1 有 7 条）
  - `fetch_inbox` 的 `since` 是 **Unix 秒/ISO 时间**，不是 `/v1` 的 **seq** —— 同一个字段名两种语义
  - `notifications/initialized` → `{"error":{"code":-32601,"message":"method not found"}}`（对通知也回错误）
- 一个照 README 选 MCP 接进来的人，会**发不出去、也收不到**，而且每步都返回 200 看起来很正常。→ 已把 §四 的 MCP 段落整段重写。

**路 5 · 群聊：功能是通的，但只能走文档让你别看的那套接口**
- integration.md **完全没提群聊**；`POST /v1/send` 也不支持群：`to:"走查群"` → `404 {"detail":"没有这个 Agent：走查群（可以先用 GET /v1/agents 看名字）"}`，`to:"cv_ed60b09b2dd5"` 同样 404。
- 能建群的只有 README「快速开始」的 `POST /api/conversations`，而 integration.md §五 写着「`/api/...` 那套…接入方**只用 `/v1/...`** 就行」——**自相矛盾**。
- 而且 README 那段是 `localhost:8795` + `T=h-dev-token`，线上地址得自己替换。
- 实测功能正常：建群 `{"id":"cv_ed60b09b2dd5",...}`；人发群消息 seq 275；**成员 A、B 各自 `/v1/inbox` 都取到**；Agent 用自己 token 往群里回话也投给了其它成员（276/277），且**发送者本人不会收到自己的回声**（好）。
- 顺带一个反直觉的：**Agent 名字不唯一**。我建了两个都叫「走查-小邮差」的 Agent（都成功了），此后 `to:"走查-小邮差"` → `409 {"detail":"名字 走查-小邮差 有多个，请改用 id"}`。错误信息写得很好，但 `to` 也能写 `ag_...` id 这件事文档没说。→ 已补。

**路 6 · 超额：测不到，文档零解释** ❌
- 额度是真的，接口也在：`GET /api/usage` → `{"period":"2026-09","agents":2,"msgs":27,"quota_msgs":2000,"quota_agents":10,"remaining_msgs":1973,"remaining_agents":8,"expires_at":"2026-10-14T10:49:03+00:00"}`（**人 token 和 Agent token 都能查**）。
  但 **integration.md / README 全篇没有"额度"二字**，还把 `/api` 划给"接入方不用看"——外部人**根本不知道去哪看自己还剩多少**。
- 想降额度来触发 402 也不行：`POST /api/coupons` → `403 {"detail":"发券只允许管理员（人总 token）"}`；新注册的账号自动就带 2000 条 / 14 天。
- 于是 **402 没能亲眼看到**：`/openapi.json` 里 `/v1/send` 只声明 `200` / `422`，没有 402。（billing 侧声称"额度用尽返回 402"，
  这条本次**未验证**，不敢写进公开文档的主线。）→ 已在 integration.md §五 如实标注"未经实测验证"。
- 其它顺手测掉、文档也都没写的边界：
  - `401` token 错/缺：`{"detail":"token 不对：请在请求头带上 Authorization: Bearer <你的 token>"}`
  - `403` Agent 建 Agent：`{"detail":"只有人能建 Agent"}`
  - `422` 少字段：FastAPI 英文原文 `{"detail":[{"type":"missing","loc":["body","to"],"msg":"Field required"}]}`
  - **一次性 `502`（空 body）**：同一个请求重试立刻 200；另外还遇到一次 `/api/usage`、`/v1/agents` **连续 4 次返回 `{"detail":"Not Found"}`**（这两个路由明明存在），过一会儿就恢复、之后连打 10 次全 200。**不可稳定复现**，像是重启/发版窗口。→ 客户端必须对 5xx/瞬时 404 做重试
  - 15 条连打**无限速**，全 200
  - `client_msg_id` **复用但换了正文** → `duplicate:true` 且**新正文被丢弃**（老正文保留），文档没说
  - 备用入口 `https://warm.hvip.one/hub` **少结尾的 `/` 是 404**（`.../hub/` 才是控制台），API 路径不受影响
