# 记忆分层规范（v0.1 · 2026-10-05 起草，等 5 个岗位 Agent 反馈后定稿）

> 目标：**让 Agent 轻装上阵** —— 每次醒来只读一小份"索引"，细节用本地检索去取；
> **每台岗位机都是独立服务器，本地磁盘/常驻进程要充分利用**，不要把所有东西塞进模型上下文。

---

## 一、三层记忆

| 层 | 放哪 | 大小上限 | 谁写 | 什么时候读 |
|---|---|---|---|---|
| **L0 常驻**（每次醒来必读） | 各机 `岗位/<名>/记忆/索引.md` | **≤ 60 行** | Agent 自己，每日收尾时更新 | 每次醒来 |
| **L1 项目记忆**（按需） | 各机 `岗位/<名>/记忆/<主题>.md` + 仓库 `docs/` | 每篇 ≤ 200 行 | Agent 自己 / 集成者 | 需要细节时**按主题取** |
| **L2 原始资料**（检索） | 各机 `岗位/<名>/日志/`、`工作区/`、仓库历史、邮局历史消息 | 不设限 | 自动 | **只 grep，不全读** |

**L0 只写四件事**（多一个字都不写）：
1. **我是谁 + 手上在做什么**（当前任务、`seq`、Issue 号）
2. **上次做到哪**（一句话 + 断点）
3. **必须记住的红线**（如"改公共文件先 pull""不得对外承诺"）
4. **下一步做什么**

## 二、本地检索（替代"把历史读进来"）

```bash
# 找过去的结论/坑（只出匹配行，不读全文）
rg -n "关键词" ~/工作区/岗位/<名>/记忆 ~/工作区/岗位/<名>/日志 | head -20
# 取某个主题的全文（确认了才读）
cat ~/工作区/岗位/<名>/记忆/<主题>.md
# 邮局历史：按关键词查自己收到的消息
agentpost.py inbox --grep 关键词        # （待实现，见下）
```

**原则**：**先出索引行，再看全文**；一次读入不超过 ~200 行。

## 三、每台机器该跑的常驻活（充分利用独立服务器）

| 任务 | 频率 | 干什么 | 放哪 |
|---|---|---|---|
| **每日收尾归档** | 每天 1 次 | 把当天工作摘要写进 `记忆/日志-<日期>.md`，更新 `索引.md` | 各机 cron / systemd timer |
| **大件压缩** | 每周 | 30 天前的日志压成 `.gz`；90 天前的移到 `归档/` | 同上 |
| **本地索引** | 每天 | 给 `记忆/`、`日志/` 生成 `index.json`（一行摘要 + 文件指针） | 同上 |
| **磁盘/内存体检** | 每天 | 超阈值（磁盘 >80% / 内存 >90%）写进事件流 | 同上 |
| **守候进程** | 常驻 | 收消息 → 唤醒（含 @ 唤醒、补读、值班巡视） | 已在跑 |

## 四、过期与降级规则（默认值，可按机器调）

| 内容 | 规则 |
|---|---|
| L0 索引里的"当前任务" | 任务关单后**当天**清掉，只留一行"已交付：<Issue> <日期>" |
| 日志（逐条过程） | 30 天 → 压缩；90 天 → 移入 `归档/`（仍可 grep） |
| 主题记忆 | 半年未引用 → 顶部标 `【可能过期】`，被引用时先核对再清标记 |
| 备份（服务器侧） | 本地 72 份 / 异地 7 天（已有，别改） |
| 邮局消息历史 | 永久保留（这是"不丢"的底账），但**只按需检索** |

---

## 五、谁负责

- **岗位 Agent**：维护自己的 L0/L1，每天收尾更新（这条写进它们的岗位规矩）
- **集成者（温暖）**：维护仓库 `docs/`（L1 公共部分）、**裁决"什么该降级"**、并在做记忆体检
- **老板（人）**：只看结论；需要时问"你现在记得什么"，任何人应能用 60 行内的索引回答
