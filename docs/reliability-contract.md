# 可靠性契约（v0.1）

这是本项目的**第一条卖点**，写成可验证的条款，不是营销词。

## 我们承诺
| # | 承诺 | 怎么验证 |
|---|---|---|
| 1 | **落盘才返回**：`POST …/messages` 返回 200 时，消息已在 SQLite 里 | 杀进程后重启，消息仍在；`seq` 不回退 |
| 2 | **至少一次投递**：收件人（人 / Agent）用游标 `since` 取件，期间的每条消息都会被取到 | `smoke.sh`：B 的收件箱拿到 A 之后所有消息 |
| 3 | **幂等**：同一会话内 `client_msg_id` 重复提交不产生第二条 | `smoke.sh`：重发后消息条数不变，返回第一次的 `seq` |
| 4 | **离线补投**：收件人不在线时消息按序排队，上线后按游标取走 | `smoke.sh`：新 Agent 从 `since=0` 一次拿到全部历史 |
| 5 | **全局单调 `seq`**：跨会话可用**一个**游标（收件箱要跨会话） | `seq` 严格递增，不按会话重置 |
| 6 | **每条消息可查轨迹**：会话、发起方（人 / 哪个 Agent）、时间、seq | `GET /api/conversations/{id}/messages` |

## 我们明确**不**承诺（写清楚，免得以后扯皮）
- **不承诺"恰好一次"**：我们做"至少一次 + 幂等去重"，消费方仍应按 `id` 去重
- **不承诺跨区域多活**：P2 之前是单机 + 定时备份
- **不承诺 SLA 与赔付**：P4 之后再谈，届时以单独文档另行约定
- **不承诺消息内容加密**：传输加密由网关负责（HTTPS）；静态加密在 P2 评估

## 保留期（当前）
- 消息保留：**不自动删**（数据库为准）
- P2 起：按套餐设定保留期（免费 7 天 / 标准 90 天 / 团队 1 年），到期归档而非硬删
